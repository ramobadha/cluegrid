# Gujarati vocabulary

`words.tsv` contains 2,150 unique Gujarati terms and one English equivalent for `gu-v2`. Its header specifies one column per language; `languages.tsv` provides picker names in English and each language's native script. `words-v1.tsv` preserves the original 180 pairs in their original order. `words.js` is generated by `python build.py`; do not edit it manually.

## Editorial approach

The expanded list was composed for clue-based play across everyday objects, nature, food, culture, people, places, science, and abstract ideas. It includes common Gujarati vocabulary, Gujarati-script loanwords for modern objects, and recognizable place names. It is not a bulk dictionary import. Some familiar compounds use spaces; each is a single vocabulary term.

Every vocabulary row contains exactly one Gujarati entry and one English translation. The selector controls decide which language appears as the main word and which as its meaning. Never combine synonyms, alternate spellings, or multiple definitions in a translation. A compound written as two parts can still be a single term. To add another language, add its ISO code and names to `languages.tsv`, add the code to the word-bank header, and give every row exactly one translation. Dialect choices and translations can be refined with a fluent speaker's review; automated validation does not establish linguistic correctness.

## Maintaining deterministic boards

Ordering and contents determine seeded boards. Freeze every released version. Before a future vocabulary update, archive the released bank and add a new version in `build.py` and `scripts/app.js`. Preserve all older banks; those older versions retain their original language choices when later languages are added.

Run `python build.py`, `python -m unittest discover -s tests -p "test_*.py"`, and `node --test tests/*.test.cjs` after edits. The build rejects duplicate normalized Gujarati terms, missing translations, unsupported language codes, and multiple alternatives within a translation.
